## v5.0.1 - Release housekeeping
- [Changed] Firmware version raised to 5.0.1; the version shown in the web UI, /api/status, /api/diag and the OTA page now reads v5.0.1.
- [Changed] Sidebar: the "Online" chip now shows free / total RAM (heap), refreshed from /api/status and the live channel. The chip keeps its colour as the connection indicator and reads "Offline" while the device cannot be reached.
- [Changed] Change log rewritten: the 4.2 - 4.7 intermediate releases are now documented, and 4.0 - 4.1 are summarised under v4.0.0.

## v5.0.0 - Kindle Display, remote nodes and firmware optimisation
- [Added] Kindle e-ink display: the Collector serves a dashboard to a jailbroken Kindle (KUAL extension), rendered either as a browser page or natively on the panel through FBInk with the same design.
- [Added] Kindle layout engine: a configurable list of readings in nine named places, a three-wide grid, per-place ink, centred headlines and single-item rows, readings sized as large as they fit, and a one-line indoor row with an optional two-column indoor block.
- [Added] Kindle display options: rotation 0/90/180/270 with a dedicated landscape page (panel and browser rotate independently), clock on/off, EN/BG language, week strip styles with the weekly forecast, rule settings and a text-size setting.
- [Added] Kindle operation: refresh tiers that clear ghosting, a tap menu and a screen of its own, power-button wake, radio and CPU sleep between ticks, reader clock sync from the Collector every N days, and script updates for the reader pushed through the Collector.
- [Added] Kindle content: a 24-hour chart that survives a reboot and draws from the first minutes, drawn tendency arrows, battery warnings for running-down nodes, and per-font sizing measured from each TTF's own proportions.
- [Added] Remote nodes: a common configuration contract for WiFi (ESP8266) and ESP-NOW (XIAO ESP32-C3) nodes, with runtime-configurable sensors on a shared sensor layer and a setup page styled like the Collector's.
- [Added] Node management from the Collector: edit every node's settings on the Nodes page, move nodes together with a network change, and keep readings the Collector could not accept until it can.
- [Added] Node OTA: the Collector stores node firmware images and offers them to WiFi and ESP-NOW nodes, with trial boot and automatic rollback on the node.
- [Added] Sensor corrections: dedicated offset and multiplier fields per metric, applied to node data as well; BME280/BMP280 now use forced mode with one conversion per read.
- [Added] Automatic summer/winter time (EU, US, off or manual), on-demand weather forecast refresh from three places, and Collector pin fields typed as the board labels them, with header drawing and warnings.
- [Added] Settings UI redesign: a status-first settings hub, a unified Nodes page, panel-led e-ink settings, and full English/Bulgarian translation of the web UI.
- [Added] Deploy tools: remote update of the Collector and its nodes over WiFi, a STOP button, and a Build OTA Firmware workflow with dropdowns and checkboxes.
- [Changed] Data log: sensor rows, hybrid fills and legacy runs are written to one data_log file by a single writer; the Sensors chart reads its history from it, and each column documents how it combines its interval.
- [Optimized] Firmware size: about 38 KB freed on the C3 app slot, ArduinoJson compiled once per direction, and duplicated code folded (-30 KB on the all-features C3 image), so every feature fits on the ESP32-C3.
- [Optimized] Web UI stability: /api/data and /api/latest no longer copy the whole ring buffer, the static file handler is registered after every route, the first forecast fetch waits 90 s after boot, and a Wi-Fi transmit power setting (8.5 dBm by default on the C3 Pico and Super Mini) prevents brownouts on page load.
- [Fixed] Whole-tree code review: 49 findings across 14 areas (locking, allocation failure paths, SSE client list, AP lock-out, DS1302 bus), 44 fixed; Modules page forms save enums as numbers and keep the WiFi password.

## v4.2.1 - Safe-mode + OTA rollback hardening
- [Breaking] RainSensor default pin moved from GPIO 9 to GPIO 10. GPIO 9 is an ESP32-C3 bootstrap pin; a tipped bucket at power-on triggers download mode. Existing deployments on the default pin must rewire to GPIO 10 or explicitly set "pin": 9 in platform_config.json (not recommended).
- [Fixed] Restart circuit breaker: 3 consecutive watchdog/panic resets without 60 s of healthy uptime now boot into AP-only safe mode for OTA recovery instead of looping.
- [Fixed] OTA auto-confirmation removed from restart and deep-sleep paths. A pending-verify image that crashes within 90 s now rolls back instead of being silently confirmed.
