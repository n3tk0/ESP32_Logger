MQTT

Publishes each sensor reading to {prefix}/device/{id}/sensor/{name}/{metric}. Requires an MQTT broker (e.g. Mosquitto, Home Assistant, Node-RED).

How often to flush batched readings. Default 60 000 ms.

TLS uses WiFiClientSecure with no cert verification (no CA bundle on device). Use for cloud brokers where encryption matters; plaintext is fine for local LAN.

HTTP POST

POSTs a JSON array of readings to any HTTP endpoint. Compatible with InfluxDB v2 (/api/v2/write), Grafana, custom servers.

HTTPS endpoints use TLS without certificate verification (no bundled CA store). Self-signed certs work; MITM is possible on unprotected networks.

Sent as Authorization: …. Most APIs use Bearer <token> or Basic <base64>. CRLF characters are rejected client-side; backend double-checks (HttpExporter).

Sensor.Community

Sends PM2.5/PM10 and environmental data to sensor.community. Register your device at the site first to get a chip ID. The device ID is your ESP32 MAC-derived ID (shown in Device settings). Send interval must be ≥ 145 seconds (API requirement).

openSenseMap

Sends readings to opensensemap.org. Create a senseBox at the site, then copy the Box ID, access token and sensor IDs below.

⚠ Tokens stored on device in plaintext (LittleFS). Treat this device like a long-lived API key holder; revoke and rotate via opensensemap.org if the device is lost or re-flashed.
